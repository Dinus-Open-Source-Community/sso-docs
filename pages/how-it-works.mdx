# Cara Kerja SSO

DOSCOM SSO mengimplementasikan **Authorization Code Flow** — alur standar OAuth 2.0
yang dipakai Google, GitHub, dan provider besar lainnya.

## Konsep Dasar

```
Aplikasimu  ←──HTTP──→  SSO Server  ←──Login──→  User
```

Aplikasimu **tidak pernah** melihat password user. SSO yang menangani autentikasi,
lalu mengirimkan token ke aplikasimu sebagai bukti bahwa user sudah login.

## Alur Lengkap (Authorization Code + PKCE)

<Steps>

### Redirect ke SSO

Aplikasi redirect browser user ke endpoint `/authorize` dengan parameter:

```
GET https://sso.doscom.org/authorize
  ?client_id=CLIENT_ID
  &redirect_uri=https://appkamu.com/callback
  &response_type=code
  &scope=openid profile email
  &state=RANDOM_STRING
  &code_challenge=PKCE_CHALLENGE         ← wajib untuk public client
  &code_challenge_method=S256
```

**`state`** wajib diisi — nilai acak yang kamu simpan untuk verifikasi CSRF.

### User Login di SSO

SSO menampilkan halaman login. Alurnya selalu lewat **OTP email 6 digit**:

1. User memasukkan email + password (atau daftar akun baru lewat form register).
2. SSO mengirim kode OTP ke email — user memasukkan kode di halaman verifikasi.
3. Kalau user sudah punya session aktif (`session_id`, 30 hari), SSO langsung
   tampilkan *account chooser* — pilih akun tersimpan (tetap wajib OTP,
   kecuali perangkat sudah ditandai terpercaya 30 hari).

Akun tanpa password (mis. dibuat via bind) wajib atur password lewat alur
*Lupa password* dulu sebelum bisa login form.

### SSO Redirect Balik ke Aplikasi

Setelah login sukses, SSO redirect ke `redirect_uri` kamu dengan:

```
https://appkamu.com/callback?code=AUTH_CODE&state=STATE_SAMA
```

Verifikasi bahwa `state` yang diterima sama dengan yang kamu kirim.

### Tukar Code dengan Token

Di server-side (bukan browser), POST ke `/token`:

```http
POST /token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=AUTH_CODE
&redirect_uri=https://appkamu.com/callback
&client_id=CLIENT_ID
&client_secret=CLIENT_SECRET          ← untuk confidential client
&code_verifier=PKCE_VERIFIER          ← untuk public client
```

Response:

```json
{
  "access_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "opaque_string",
  "id_token": "eyJ..."
}
```

### Ambil Data User (Opsional)

Pakai `access_token` untuk memanggil `/userinfo`:

```http
GET /userinfo
Authorization: Bearer ACCESS_TOKEN
```

Response — profil lengkap user (tanpa filtering scope; scope `profile`/`email` hanya memengaruhi klaim di `id_token`):

```json
{
  "id": 4,
  "name": "Nama User",
  "email": "user@doscom.org",
  "avatar_url": "https://cdn.doscom.org/avatars/4.png",
  "bind": [{ "client_id": "CLIENT_ID_KAMU", "name": "Nama Aplikasimu" }],
  "email_verified": true,
  "created_at": "2025-01-01T00:00:00Z"
}
```

Field `bind` adalah array keterikatan akun ke aplikasi — **otomatis terisi
saat user berhasil login OAuth ke aplikasimu** (`RecordSSOApp`). Satu akun
bisa terikat ke banyak aplikasi. `bind` kosong/`null` = belum ter-bind ke
aplikasi manapun.

> Implementasi referensi awal (login + sinkronisasi bind + verifikasi
> `bind_token`, sebelum OTP bind): repo `DummyWebSSO` (`server.js`, `sso.js`,
> `config.js`). Alur di SSO kini mewajibkan langkah OTP setelah form bind —
> sesuaikan dengan [Auth API — Bind](/auth-api).

</Steps>

## Bind Akun Pihak Ketiga (tanpa OAuth penuh)

Selain "Login with Doscom", aplikasi bisa menautkan akun lokal yang sudah ada
ke SSO via **Bind API** (`POST /api/auth/bind`):

1. Backend memanggil `POST /api/auth/bind` dengan
   `{ name, email, client_id, return_url }` → menerima `url` form bind SSO.
2. Tampilkan URL itu ke user — user mengisi/konfirmasi form di SSO.
3. SSO menyimpan niat bind + mengirim kode OTP `bind_account` ke email user,
   lalu redirect ke halaman input OTP (`/api/auth/bind/otp?token=<PENDING>`).
   User memasukkan 6 digit kode (bisa kirim ulang bila kedaluwarsa).
4. Setelah OTP benar dan bind dieksekusi, SSO redirect browser ke
   `{return_url}?bind_token=<JWT>`.
5. Backend verifikasi `bind_token` (RS256 via JWKS): cek `iss`, `aud` =
   `client_id` sendiri, `event` = `account.bind`, `exp` (±5 menit) →
   tautkan akun lokal.
6. Sinkronisasi ulang via `GET /api/auth/binding/status?email=&client_id=`
   — **hanya** untuk akun yang ter-bind lokal (jangan hit untuk akun
   lokal/non-SSO).

Detail request/response + contoh verifikasi: lihat [Auth API — Bind](/auth-api).

## Dua Jenis Client

| Tipe | Kapan dipakai | Secret | PKCE |
|------|--------------|--------|------|
| **Confidential** | App dengan backend server (Node, Go, PHP, Python) | Ya | Opsional |
| **Public** | SPA / mobile app (tidak bisa simpan secret) | Tidak | **Wajib** |

<Callout type="info">
  **Daftar aplikasimu dulu** di Developer Console untuk mendapatkan `client_id` dan `client_secret` — akun developer dibuat oleh admin/super_admin, tidak ada pendaftaran mandiri.
</Callout>

### Cara daftar aplikasi

1. Buka **Developer Console** di `https://sso.doscom.org/developer/login` (login dengan akun developer dari admin — auth memakai cookie HttpOnly `dev_portal`, bukan localStorage).
2. Klik **+ Aplikasi baru**, isi nama aplikasi dan pilih tipe client (confidential/public).
3. Isi **Redirect URI** — alamat callback aplikasimu, misal `https://appkamu.com/callback`.
4. Setelah dibuat, **simpan `client_secret` segera** — hanya tampil sekali, tidak bisa dilihat lagi.

Aturan redirect URI:

| Ketentuan | Keterangan |
|-----------|------------|
| Wajib `https://` | Kecuali `http://localhost` / `http://127.0.0.1` untuk pengembangan |
| Tanpa fragment (`#`) | URL fragment tidak diperbolehkan (RFC 6749) |

> Client ID/Secret disimpan di environment variable aplikasimu (misal `SSO_CLIENT_ID`), jangan di-commit ke repository.

## Token yang Diterima

| Token | Format | Kegunaan | Masa berlaku |
|-------|--------|----------|-------------|
| `access_token` | JWT RS256 | Panggil `/userinfo`, resource API | 1 jam |
| `id_token` | JWT RS256 | Verifikasi identitas user (OIDC) | 1 jam |
| `refresh_token` | Opaque string | Perbarui access token tanpa login ulang | 30 hari |

### Verifikasi `id_token`

`id_token` adalah JWT yang bisa diverifikasi secara lokal dengan public key SSO:

```
JWKS URL: https://sso.doscom.org/.well-known/jwks.json
Algoritma: RS256
Issuer (iss): https://sso.doscom.org
Audience (aud): CLIENT_ID kamu
```

Gunakan library JWT di bahasamu masing-masing — tidak perlu koneksi ke SSO untuk verifikasi.

## Refresh Token

Refresh token **di-rotate** setiap kali dipakai — token lama langsung tidak berlaku:

```http
POST /token/refresh
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&refresh_token=REFRESH_TOKEN
&client_id=CLIENT_ID
&client_secret=CLIENT_SECRET
```

<Callout type="warning">
  Simpan refresh token terbaru segera setelah menerima response refresh.
  Kalau refresh token lama dipakai lagi (reuse), **seluruh refresh token keluarga user di aplikasimu akan dicabut** (diduga dicuri).
</Callout>

## Portal Akun & Developer Console

- **Portal Akun** (`https://sso.doscom.org/`) — dashboard end-user "Akun
  doscom": login/register OTP, edit profil, upload avatar, ganti password,
  lepas aplikasi (unbind + revoke token), hapus akun dari perangkat. Lihat
  [Portal Akun](/account-portal).
- **Developer Console** (`/developer/*`) — daftarkan aplikasi OAuth, kelola
  redirect URI, regenerate secret. Lihat [Developer Console](/developer-console).
