# Auth API — `/api/auth/*`

API JSON untuk mengelola akun DOSCOM (tanpa alur redirect OAuth).
Endpoint yang aktif saat ini: **transfer akun** (`/transfer`) dan
**ganti password** (`/change-password`). Profil user kini diambil lewat
`GET /userinfo` (OAuth) — lihat [Endpoint Referensi](/endpoints).

Base URL: `https://sso.doscom.org` (development: `http://localhost:8080`)

<Callout type="warning">
  Endpoint `POST /api/auth/register`, `POST /api/auth/login`,
  `GET /api/auth/verify-email`, `POST /api/auth/forgot-password`,
  `POST /api/auth/reset-password`, dan `GET /api/auth/me` sedang
  **dinonaktifkan/dihapus**. Pembuatan akun baru
  saat ini hanya lewat [alur OAuth SSO](/how-it-works) atau endpoint `/transfer`.
</Callout>

## Format Response

Semua endpoint mengembalikan envelope yang sama:

**Sukses** (HTTP 2xx):

```json
{
  "status": true,
  "message": "account transferred",
  "data": { }
}
```

**Error** (HTTP 4xx/5xx):

```json
{
  "status": false,
  "message": "unauthorized",
  "errors": "detail error"
}
```

## Autentikasi

Endpoint `/change-password` membutuhkan header:

```http
Authorization: Bearer TOKEN_JWT
```

`TOKEN_JWT` adalah JWT user (`kind: user`) yang ditandatangani HS256 dengan
secret milik SSO server — verifikasi dilakukan server-side oleh endpoint yang
memakainya, bukan verifikasi lokal seperti `id_token` OAuth.

Endpoint `/transfer` berbeda: membutuhkan token portal developer
(`kind: developer` — Bearer atau cookie `dev_portal`) dengan role
**SuperAdmin**, karena ini operasi sensitif migrasi akun antar sistem.

## Objek User

```json
{
  "id": 4,
  "name": "Budi Santoso",
  "email": "budi@doscom.org",
  "avatar_url": "https://cdn.doscom.org/avatars/4.png",
  "type": "d-form",
  "email_verified": true,
  "created_at": "2025-01-01T00:00:00Z"
}
```

Field `type` menandai asal akun (hasil `/transfer`): `d-form`, `google`,
`github`, dll. Bentuk objek ini juga yang dikembalikan `GET /userinfo`.

## POST /api/auth/transfer 🔒 SuperAdmin

Pindahkan (registrasikan) akun user dari sistem lain ke SSO. Endpoint ini
dipakai oleh aplikasi/sistem lain — **bukan end user** — dan wajib memakai
token portal developer SuperAdmin.

Dua use case utama:

1. **Migrasi data** — akun user sudah banyak tersimpan di database website
   lain (mis. D-Form) dan ingin dipindahkan ke SSO. Kirim data tiap user
   dengan `type: "d-form"` (atau nama sistem asalnya).
2. **Login pihak ketiga** — user login via Google, GitHub, atau provider
   lain di aplikasi kamu. Setelah login berhasil, kirim datanya ke SSO agar
   tersimpan di sana dengan `type: "google"`, `type: "github"`, dst.

<Callout type="info">
  Nilai `type` bebas (2–50 karakter), tapi dipakai untuk menandai asal akun.
  Gunakan nama yang konsisten: `d-form` untuk migrasi D-Form,
  `google`/`github` untuk login pihak ketiga.
</Callout>

**Request** (`application/json`)

| Field | Wajib | Validasi | Keterangan |
|-------|-------|----------|------------|
| `name` | Ya | 3–100 karakter | Nama user |
| `email` | Ya | Format email, maks 150 karakter | Email user (akan di-lowercase) |
| `avatar_url` | Tidak | Harus URL yang valid | Foto profil dari sistem asal |
| `type` | Ya | 2–50 karakter | Asal akun: `d-form`, `google`, `github`, dll. |
| `email_verified` | Tidak | `true`/`false` | `true` bila email sudah terverifikasi di sistem asal (mis. terverifikasi oleh Google/GitHub) |

**Response** `201 Created` — `data` berisi objek user yang baru dibuat:

```json
{
  "status": true,
  "message": "account transferred",
  "data": {
    "id": 4,
    "name": "Budi Santoso",
    "email": "budi@doscom.org",
    "avatar_url": "https://lh3.googleusercontent.com/...",
    "email_verified": true,
    "created_at": "2025-01-01T00:00:00Z"
  }
}
```

**Error**:
- `400 Bad Request` — validasi gagal
- `401 Unauthorized` — token bukan portal developer / bukan SuperAdmin
- `409 Conflict` — email sudah terdaftar di SSO

<Callout type="warning">
  Akun hasil transfer dibuat **tanpa password**. Jika nanti user butuh
  password (mis. untuk login form SSO), gunakan `POST /api/auth/change-password`
  setelah user mendapatkan token, atau aktifkan kembali alur reset password.
</Callout>

## Profil User — `GET /userinfo`

Pengambilan profil user tidak lagi lewat `GET /api/auth/me` (dihapus).
Gunakan endpoint OAuth [`GET /userinfo`](/endpoints#get-userinfo) dengan
access token dari alur OAuth (RS256):

```http
GET /userinfo
Authorization: Bearer ACCESS_TOKEN
```

**Response** `200 OK` — objek user lengkap (lihat [Objek User](#objek-user)).

## POST /api/auth/change-password 🔒

Ganti password user yang sedang login (wajib tahu password lama).

**Request** (`application/json`)

| Field | Wajib | Validasi |
|-------|-------|----------|
| `current_password` | Ya | |
| `new_password` | Ya | 8–72 karakter |

**Response** `200 OK` — `{ "status": true, "message": "password changed" }`

**Error**: `400` password lama salah, `401` token tidak valid.

```bash
curl -X POST https://sso.doscom.org/api/auth/change-password \
  -H "Authorization: Bearer TOKEN_JWT" \
  -H "Content-Type: application/json" \
  -d '{"current_password": "rahasia123", "new_password": "baru45678"}'
```
