# Admin — Kelola User

Halaman manajemen tersedia di:

```
https://sso.doscom.org/admin/users
```

Halaman ini mengelola **akun developer** (`/api/developer/accounts` — akun
portal: `developer` / `admin`, plus `super_admin` yang sudah ada). Auth memakai
cookie `dev_portal` yang sama dengan Developer Console (tidak ada input token
manual di UI — `fetch` mengirim cookie otomatis).

<Callout type="warning">
  Halaman ini hanya bisa diakses oleh role **admin** atau **super_admin**
  (guard `portalCookieGuard` + `requireAdmin`). Tombol "Kelola User" di
  Developer Console hanya muncul untuk role tersebut.
</Callout>

---

## Dua tabel akun (jangan tertukar)

| Tabel | Isi | Role | Dikelola lewat |
|---|---|---|---|
| `users` | End-user OAuth (akun "Login with Doscom" biasa) — **tanpa role**, semua setara member | — (tidak ada kolom role) | `GET/PUT/DELETE /api/users/*` (tanpa halaman UI khusus; registrasi publik hanya via alur OAuth `/register` + OTP atau bind) |
| `developers` | Akun portal (Developer Console + Admin) | `developer` (kelola app sendiri) \| `admin` (lihat semua app + user) \| `super_admin` (semua operasi) | Halaman `/admin/users` + `GET/POST/PUT/DELETE /api/developer/accounts` |

PII (`name`, `email`, `avatar_url`) di kedua tabel disimpan ter-enkripsi
AES-256-GCM; kolom `bind` di `users` tidak dienkripsi (struktur bebas, bukan
PII langsung).

---

## Halaman `/admin/users` — kelola akun developer

Tabel menampilkan: ID, Nama, Email, Role, waktu dibuat — dengan aksi
Ubah/Hapus per baris dan form Tambah akun.

### Buat akun developer (super_admin saja)

| Field | Validasi |
|-------|----------|
| **Nama** | min 3, maks 100 karakter |
| **Email** | format email valid, maks 150 karakter (unik, di-lowercase) |
| **Password** | min 8, maks 72 karakter |
| **Role** | `developer` atau `admin` saja |

<Callout type="info">
  Role `super_admin` **tidak bisa** dipilih saat membuat user dari UI maupun
  API (`oneof=admin developer`) — `super_admin` dibuat via seeder
  (`EnsureSuperAdmin` / `ADMIN_EMAIL` + `ADMIN_PASSWORD`). Kamu juga tidak bisa
  menghapus akunmu sendiri (anti-lockout).
</Callout>

### Edit / hapus akun developer (super_admin saja)

- Edit: `name`, `email`, `password` (opsional), `role` (`admin`/`developer`).
- Hapus: soft delete (data tersimpan di DB, tidak muncul di list).

## API Endpoint (untuk integrasi programatik)

Semua endpoint management memakai guard `PortalStrategy`: token **akun
developers** (`kind: developer`) via header `Authorization: Bearer ...`
**atau** cookie `dev_portal` (halaman admin memakai cookie). Token
`kind: user` ditolak.

### Akun developer — `/api/developer/accounts`

| Method | Path | Role | Keterangan |
|--------|------|------|-----------|
| `GET` | `/api/developer/accounts` | admin, super_admin | List semua akun developer |
| `GET` | `/api/developer/accounts/:id` | admin, super_admin | Detail akun developer |
| `POST` | `/api/developer/accounts` | super_admin | Buat akun (`name`, `email`, `password`, `role: admin\|developer`) |
| `PUT` | `/api/developer/accounts/:id` | super_admin | Update akun |
| `DELETE` | `/api/developer/accounts/:id` | super_admin | Hapus akun (tidak bisa hapus diri sendiri) |

```bash
curl -X POST https://sso.doscom.org/api/developer/accounts \
  -H "Authorization: Bearer TOKEN_DEVELOPER_SUPER_ADMIN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Admin Baru",
    "email": "adminbaru@doscom.org",
    "password": "password123",
    "role": "admin"
  }'
```

### End-user OAuth — `/api/users`

| Method | Path | Role | Keterangan |
|--------|------|------|-----------|
| `GET` | `/api/users` | admin, super_admin | List end-user |
| `GET` | `/api/users/:id` | admin, super_admin | Detail end-user |
| `PUT` | `/api/users/:id` | super_admin | Update (`name`, `email` saja — tidak ada `role`/`is_developer`) |
| `DELETE` | `/api/users/:id` | super_admin | Hapus user (soft delete) |

<Callout type="info">
  Tidak ada `POST /api/users` — akun end-user **tidak dibuat lewat API**.
  Registrasi publik hanya lewat alur OAuth (`POST /register` + OTP) atau alur
  bind (`POST /api/auth/bind/form`). Response user kini memakai field `bind`
  (`[{client_id, name}]`), bukan `type` lama.
</Callout>

**Response user (`201`/`200`):**

```json
{
  "status": true,
  "message": "user fetched",
  "data": {
    "id": 5,
    "name": "Budi Santoso",
    "email": "budi@doscom.org",
    "avatar_url": "https://cdn.doscom.org/avatars/....png",
    "bind": [{ "client_id": "abc123", "name": "DummyWebSSO" }],
    "email_verified": true,
    "created_at": "2025-01-01T00:00:00Z"
  }
}
```
